# 访客预览模式设计说明

## 背景

AllôTCF 当前需要登录后才能进入题库、做题、复盘、错题本和收藏练习。对于第一次访问的用户来说，如果必须先注册账号，可能会在真正理解产品价值前流失。

访客预览模式的目标，不是让访客长期免费使用完整学习服务，而是让访客能低门槛看到网站的完整功能结构，并体验少量关键动作。

## 产品目标

- 访客无需注册即可进入网站。
- 访客可以看到所有主要功能入口和页面。
- 访客可以有限度地试用会改变学习状态的功能。
- 达到限制后不强制退出，仍允许继续浏览。
- 引导访客在理解产品价值后注册或登录。

## 设计原则

- 浏览不设限，关键动作设限。
- 尽量复用现有用户、题库、练习、错题和收藏逻辑。
- 访客身份在后端真实存在，避免前端单独维护一套临时学习系统。
- 访客数据和正式用户数据明确区分。
- 限制提示要温和，不打断普通浏览。

## 访客入口

登录页新增 `访客预览` 按钮。

用户点击后：

1. 前端调用访客登录接口。
2. 后端创建或返回一个访客用户。
3. 后端返回 JWT。
4. 前端按正常登录态保存 token。
5. 页面跳转到题库列表页。

访客在页面顶部或用户信息处显示为：

```text
访客预览
```

## 访客身份

后端继续使用现有 `users` 表承载访客身份，但需要能区分正式用户与访客用户。

建议在 `users` 表增加字段：

- `user_type`：`REGISTERED` 或 `GUEST`。
- `guest_action_count`：访客已使用的关键动作次数。
- `guest_action_limit`：访客关键动作上限，第一版为 10。
- `guest_expires_at`：访客身份过期时间，第一版可先预留字段。

访客用户邮箱可使用系统生成格式：

```text
guest_<随机码>@guest.allotcf
```

昵称可显示为：

```text
访客用户
```

## 关键动作限制

访客预览第一版限制 `10 次关键动作`。

不计次数的行为：

- 打开网站。
- 切换页面。
- 查看题库列表。
- 查看套题详情。
- 查看错题本列表。
- 查看收藏练习列表。
- 查看今日复习列表。
- 打开筛选项。
- 查看复盘页面。

计入次数的关键动作：

- 开始练习。
- 提交套题。
- 保存当前进度并退出。
- 重新练习。
- 错题复习中提交答案。
- 收藏题目。
- 取消收藏题目。
- 收藏练习中提交答案。

计数原则：

- 只有后端确认动作成功后才增加次数。
- 如果动作失败，不消耗次数。
- 同一次接口请求最多消耗 1 次。
- 普通浏览永远不消耗次数。

## 达到限制后的行为

当访客已使用 10 次关键动作后：

- 不强制退出。
- 不清空当前页面。
- 仍允许继续浏览所有页面。
- 再次触发关键动作时，后端返回明确的访客限制错误。
- 前端展示自定义中文弹层。

弹层文案：

```text
访客预览次数已用完
注册或登录后可继续保存进度、复盘错题和收藏题目。
```

按钮：

- `去注册`
- `继续浏览`

`继续浏览` 关闭弹层，不执行本次关键动作。

## 数据策略

第一版访客数据保存在数据库中，并归属于访客用户。

这样访客可以真实体验：

- 自动保存进度。
- 提交后复盘。
- 错题累计。
- 今日复习。
- 收藏题目。
- 收藏练习。

但访客数据不承诺长期保存。页面需要在适当位置提示：

```text
当前为访客预览，学习记录可能不会长期保留。
```

## 注册后的数据迁移

第一版不做访客数据合并。

原因：

- 数据合并涉及账号安全、重复题目、错题累计、收藏冲突和进度冲突。
- 当前目标是降低首次体验门槛，不是建立完整账号迁移系统。

后续可以增加：

- 访客注册时提示是否保留当前访客数据。
- 将访客用户升级为正式用户。
- 或将访客数据合并到已有正式账号。

## 后端接口建议

新增访客登录接口：

```http
POST /api/auth/guest
```

返回：

```json
{
  "token": "...",
  "email": "guest_xxx@guest.allotcf",
  "nickname": "访客用户",
  "userType": "GUEST",
  "guestActionCount": 0,
  "guestActionLimit": 10
}
```

关键动作接口在执行业务前检查访客剩余次数：

- 如果未超过限制，执行业务，成功后计数加 1。
- 如果已超过限制，返回 `403` 和错误码 `GUEST_LIMIT_REACHED`。

建议错误响应：

```json
{
  "code": "GUEST_LIMIT_REACHED",
  "message": "访客预览次数已用完，注册或登录后可继续保存进度、复盘错题和收藏题目。"
}
```

## 前端页面建议

登录页：

- 保留邮箱密码登录。
- 保留注册入口。
- 新增 `访客预览` 次级按钮。

全站顶部：

- 正式用户显示昵称。
- 访客显示 `访客预览`。
- 可显示剩余次数，例如 `剩余 8 次关键动作`。

关键动作触发限制时：

- 使用与当前页面风格一致的中文弹层。
- 不使用浏览器原生弹窗。

## 测试重点

后端：

- 访客登录能创建访客用户并返回 JWT。
- 正式用户不受访客次数限制。
- 访客执行关键动作成功后次数加 1。
- 访客达到 10 次后，关键动作返回 `GUEST_LIMIT_REACHED`。
- 浏览类接口不消耗次数。

前端：

- 登录页显示 `访客预览`。
- 点击后进入题库列表。
- 访客可以浏览题库、错题本、收藏练习。
- 访客执行关键动作后剩余次数更新。
- 达到限制后弹出中文引导弹层。
- 点击 `去注册` 跳转注册页。
- 点击 `继续浏览` 留在当前页面。

## 本次范围

本次做：

- 访客登录。
- 访客关键动作 10 次限制。
- 访客模式 UI 提示。
- 达到限制后的注册引导。
- 完整复用现有学习功能。

本次不做：

- 访客数据合并到正式账号。
- 手机验证码或第三方登录。
- 管理后台查看访客数据。
- 复杂反作弊。
